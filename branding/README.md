# MultiDroid: one identity and verified releases

The official vector is `docs/design/icone/multidroid-icon.svg`. Colors and geometry come from `docs/design/tokens.json`. The site, Rust window icon, Windows executable, NSIS installer, Linux desktop icons, macOS icon and DMG use that source. The native Mac app retains Icon Composer layers from the same source.

Regenerate with Python 3, Pillow 11.3.0 and CairoSVG 2.8.2 (`cairo` is required). On Apple Silicon Homebrew, use `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib python3 scripts/sync-brand.py`. Commit the generated assets and `branding/manifest.json`. `python3 scripts/check-brand.py` rejects stale outputs.

Generated Apple bundles are copied to an isolated temporary directory before signing, so file-provider Finder metadata cannot invalidate their signature.

The site uses system fonts and static HTML. Deployment stages asset URLs using content hashes, so new icons and styles update automatically while unchanged files remain cacheable. Release links are generated by `scripts/update-site-downloads.py` from existing public GitHub assets; visitors do not call the GitHub API. OS symbols are Simple Icons (CC0) and the Windows platform mark. Store badges are absent until real listings exist.

## Pipeline

- Native stable: `mac/VERSION` (0.2.1), Apple Silicon, macOS 26+.
- Desktop preview: `rust/Cargo.toml` (0.3.0, with prerelease tags), Mac Apple Silicon, Windows x86-64 and Linux x86-64. The core currently chooses host-specific emulator packages; other CPU architectures must not be advertised without implementing and testing that selection.
- Push a matching version tag, or dispatch `release.yml` with the tag. `publish=false` validates and builds without publishing. Its optional `platform` selector can isolate Windows, Linux or Mac when diagnosing a failure; production publication rejects partial platform selections.
- Mac signs on the existing trusted Mac runner using its Developer ID Application certificate. Repository secrets `APPLE_ID` and `APPLE_APP_PASSWORD` authenticate notarization. `APPLE_TEAM_ID` defaults to the owner's existing team `6EZ89E2F5S`.
- Signing submits a temporary app ZIP to Apple, staples the app, builds the branded DMG, then signs, notarizes, staples and assesses the DMG. The temporary ZIP is never a release asset.
- Windows NSIS uses the shared ICO and branded header/sidebar bitmaps. No Windows code-signing certificate has been configured; do not label Windows as signed.
- Publication requires the complete expected installer set and a successful Mac verification job. Assets are first uploaded to a draft; public publication happens only after checking the remote file set, sizes and available GitHub digests. SHA256SUMS.txt and release.json record integrity and provenance. Files are not manually replaced in an existing release.
- After publishing, the pipeline refreshes the site's static download fallbacks, commits them to main, and dispatches `deploy-site.yml`. Both native and preview lines stay distinct.

## Validation

Run `python3 -m unittest discover -s tests`, `python3 scripts/check-brand.py`, `bash -n scripts/sign-apple-release.sh`, and actionlint with `.github/actionlint.yaml`. Production acceptance additionally requires real builds and Apple notarization; YAML checks alone do not prove the installers work.

The new Mac code reuses one color space for a screen stream instead of allocating one for every frame. Toast dismissal respects task cancellation, so replacing a banner cannot immediately clear its replacement. No performance percentage is claimed without measurement.
